    Tujuan proyek

    Mengoptimalkan pemahaman, bukan fitur

    Domain bisnis dikunci sejak awal: users, tasks, task_results, task_logs.

    Proyek ini adalah lab arsitektur. Logika bisnisnya cukup kecil untuk dipahami dalam lima menit, supaya seluruh perhatian tertuju pada pertanyaan yang sebenarnya penting di sistem nyata: masalah apa yang diselesaikan setiap komponen, apa yang terjadi jika komponen itu dihapus, apa yang terjadi jika gagal, dan berapa harganya.

    Sistem ini tumbuh bertahap dari satu proses FastAPI menjadi lima EC2 instance di private network, dan setiap penambahan harus dibenarkan oleh masalah yang terukur. Hasil akhirnya realistis tapi tetap terjangkau untuk satu developer — dan jujur soal bagian yang belum highly available.

    Yang dilatih

    • Backend modular: layer, dependency injection, validasi, error contract
    • PostgreSQL: transaction, index, compare-and-set, migration
    • Redis: cache-aside, TTL, invalidation, stampede, rate limiting
    • RabbitMQ: ack/nack, prefetch, retry queue, dead-letter, idempotency
    • Jaringan AWS: VPC, subnet, route table, NAT, Security Group, DNS, TLS
    • Operasional: Linux, Docker, Prometheus, Grafana, CI/CD, load & chaos testing

    Yang sengaja bukan tujuan

    • Fitur bisnis yang kaya — domainnya tidak akan bertambah
    • High availability multi-AZ — dibahas, tidak dibangun, demi biaya
    • Kubernetes — Compose per host lebih transparan untuk belajar
    • Menambah teknologi tanpa alasan — setiap komponen harus lulus delapan pertanyaan

    Setiap langkah membeli sesuatu, dan membayar sesuatu

    1. Single server

      Satu proses FastAPI menjawab request.

      Data hilang saat restart

    2. Modular backend

      Route, service, repository dipisah; dependency injection.

      Indirection

    3. PostgreSQL

      Source of truth dengan constraint dan transaction.

      Batas koneksi, migration

    4. Redis

      Cache-aside untuk read, counter rate limit bersama.

      Stale data, invalidation

    5. RabbitMQ + worker

      Pekerjaan lama keluar dari request; 202 Accepted.

      Duplikat, dual write

    6. Docker

      Satu image immutable dari laptop sampai EC2.

      Keanehan network/firewall

    7. Nginx + replika

      3 API, 2 worker, load balancing round robin.

      Proxy header, health check

    8. VPC & 5 EC2

      Public/private subnet, NAT, Security Group per role.

      Partial failure, SPOF bertambah

    9. DNS + HTTPS

      Elastic IP, Let’s Encrypt, redirect, HSTS.

      Renewal, rate limit

    10. Prometheus + Grafana

      Metrics dari 11 proses, alert berbasis gejala.

      Cardinality

    11. CI/CD

      GitHub Actions → ECR → SSM, rolling deploy, rollback.

      Pipeline jadi infrastruktur kritis

    12. Load & chaos test

      k6 1 vs 2 vs 3 API; merusak setiap komponen.

      Semua celah jadi terlihat
