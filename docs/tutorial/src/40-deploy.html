Apa yang diajarkan deployment ini — dan batasannya

  • Yang berhasil: container, volume, restart policy, healthcheck, log di host sungguhan; production termurah yang masih layak untuk produk kecil (~$20/bulan).
  • Yang tidak: build di server berarti compiler dan source code ada di host production, build berebut CPU dengan traffic, dan tidak ada artifact untuk rollback. Langkah 25 memperbaikinya dengan image dari ECR.
  • Satu failure domain: instance berhenti → semuanya berhenti. Itulah trade-off jujur untuk $20.
Error yang sering muncul
  • Build ter-kill / host tidak responsif — kehabisan memori saat pip install; swap file dari bootstrap membantu, atau build image di CI (langkah 34).
  • permission denied while trying to connect to the Docker daemon socket — pakai sudo atau tambahkan user ke grup docker.
  • Tidak bisa mengakses :8080 — rule SG sementara belum ada, atau Anda memakai private IP dari luar.

Boleh berbagi server: service stateless apa pun, exporter dengan targetnya, Prometheus dengan Grafana. Sebaiknya diisolasi: database dari aplikasi (noisy neighbour, blast radius), apa pun yang public dari apa pun yang menyimpan data.

Sizing

Footprint saat idle yang terukur: API ≈ 90 MB RSS, worker ≈ 110 MB + process pool, RabbitMQ ≈ 150 MB, PostgreSQL 512 MB shared buffers + ~10 MB/koneksi, Redis ≤ 256 MB, Prometheus ≈ 300 MB (bertambah seiring jumlah series), Grafana ≈ 120 MB. t3.small (2 GiB) cukup lega untuk dua container aplikasi; node data mendapat 4 GiB untuk buffer dan page cache PostgreSQL.

Semuanya 200 meskipun ada error di log: GET yang gagal di api-2 di-retry secara transparan ke server berikutnya (proxy_next_upstream). Setelah 3 kegagalan dalam 10 detik, api-2 dilewati sepenuhnya sampai fail_timeout habis. Coba dengan POST — Nginx tidak akan me-retry, dan sesekali Anda akan melihat 502. Sekarang stop seluruh instance node app: kegagalan berubah menjadi timeout (proxy_connect_timeout 3 detik), bukan refused, dan latency melonjak sebelum failover terjadi.

Langkah-langkah

DNS di registrar (Cloudflare, Niagahoster, Namecheap…): tambahkan record type A, name api, value <Elastic IP edge>, TTL 300. Di Cloudflare set Proxy status: DNS only (awan abu-abu) — jika tidak, Cloudflare yang melakukan TLS termination dan HTTP-01 berperilaku berbeda.

Route 53 (opsional, $0,50/bulan per hosted zone): Route 53 → Hosted zones → Create hosted zone example.com, public. Salin empat record NS ke registrar Anda. Create record: name api, type A, value EIP, TTL 300. (Dengan ALB Anda akan memakai record Alias — query gratis dan mengikuti IP ALB yang berubah-ubah.)

Traffic dari Nginx ke API, dan dari API ke PostgreSQL, tidak dienkripsi di dalam VPC. AWS sudah mengenkripsi traffic antar instance Nitro modern di level hardware, dan Security Group membatasi siapa yang boleh mengirimnya. Regulasi compliance (PCI, HIPAA) sering tetap mewajibkan TLS di mana-mana: PostgreSQL ssl=on + sslmode=verify-full, TLS untuk Redis, AMQPS, atau service mesh dengan mTLS. Pahami trade-off yang Anda ambil.
Error yang sering muncul
  • Timeout during connect (likely firewall problem) — port 80 tidak dibuka ke 0.0.0.0/0; Let’s Encrypt memvalidasi dari banyak IP yang tidak dipublikasikan.
  • too many certificates already issued — kena rate limit karena request production berulang; gunakan --staging saat mencoba-coba.
  • Nginx gagal: cannot load certificate "/etc/letsencrypt/live/…" — template HTTPS diaktifkan sebelum sertifikat terbit; set NGINX_SITE_TEMPLATE=edge-http, recreate nginx, terbitkan sertifikat, lalu ganti kembali.
  • Browser memberi peringatan setelah renewal — Nginx belum di-reload; unit service di atas sudah melakukannya.
